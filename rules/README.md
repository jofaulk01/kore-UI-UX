# Design rules

The handful of rules that separate "looks professional" from "looks homemade". They're written as numbers you can follow without design taste. Each file cites its sources; where sources disagree, the box says what we follow.

| File | One-line version |
|---|---|
| [spacing.md](spacing.md) | Only use spacing from the 4px scale. Related things close, unrelated things far. |
| [typography.md](typography.md) | One font, 5–6 sizes, 3 weights. Body 14px in apps. |
| [color.md](color.md) | Neutrals for almost everything, one accent, fixed status colors, 4.5:1 contrast. |
| [hierarchy.md](hierarchy.md) | One most important thing per screen. Make it win on size, weight, color or position. |
| [layout.md](layout.md) | Content in a max-width column, aligned to a grid, the important stuff top-left. |
| [motion.md](motion.md) | 150–250ms, ease-out, only to explain change. Respect "reduce motion". |
| [accessibility.md](accessibility.md) | The ten checks that make an app usable by everyone (and are often legally required). |

## The 10 rules if you read nothing else

1. **Spacing comes from a scale:** 4, 8, 12, 16, 24, 32, 48, 64. Nothing else.
2. **Group by proximity:** space inside a group is smaller than space between groups.
3. **One font.** Size and weight create hierarchy, not new fonts.
4. **Body text 14px in apps, 16px on marketing pages and phone inputs.**
5. **Mostly gray.** Color is for the one primary action, links, selection and status.
6. **Never rely on color alone:** a red badge also says "Overdue".
7. **One primary button per area.**
8. **Align everything to a few left edges.** Ragged edges are the #1 amateur tell.
9. **Every screen has a loading, empty and error version.**
10. **Use real content when designing.** Fake text hides problems with long names and big numbers.
